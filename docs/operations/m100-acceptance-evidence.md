## Findings recorded by this run

- **FIXED -- defect found by ACC-17c.** The acknowledgement id (`XACK-<attempt>-<n>`) and the reconciliation-round id (`XRND-<attempt>-<n>`) of an exit were cut with `[:64]`. The attempt id of a plan-minted MANDATORY_EXIT is 63 characters, so the sequence was cut off and the SECOND acknowledgement / round of that attempt collided with the first on the primary key: every reconcile of an automatic mandatory liquidation raised, and because `PositionPlanManager.evaluate_once` then did not isolate plans from each other, the same tick never reached later plans (now isolated, see ACC-18). Ids that already fit are unchanged; longer ones are digested (`usecases/position_exit.py::_acknowledgement_id`, `position_exit_repositories.py::_round_id`; unit tests in `tests/unit/test_m100_exit_acknowledgement_id.py`).
- **FIXED -- a partially filled entry that stays working was not protected (ACC-12, ACC-12b).** While the remainder can still fill the exit assessment refuses, so the filled shares used to carry no automatic stop, target or mandatory exit until the entry was final. `PositionPlanManager` now cancels the entry REMAINDER (bounded: at most 5 cancel requests, 15 s apart, only while the market is open; immediately on a STOP/TARGET condition or the mandatory deadline, otherwise after 120 s), reconciles by client_order_id until the entry is terminal, and only then sells the FILLED quantity (`usecases/entry_remainder_protection.py`). An entry with zero fills is never cancelled. A partially filled entry that EXPIRES is likewise a holding entry now.
- **FIXED -- a blocked approval showed no reason on the v1 console.** The v1 `/confirm-approval` override now puts the outcome into the same one-shot page flash the base route uses ('Approved, execution blocked: ...; nothing was sent'), and the ApprovedPlan is created only once an entry attempt exists (tests `test_p2_1_*`; asserted in this matrix). The durable reasons remain in `paper_submission_preview.refusals` (ACC-04b, ACC-05, ACC-06, ACC-07).
- **FIXED -- two managers racing one trigger (ACC-18).** Exactly one SELL reaches the wire (the database refuses the second preview/attempt). The loser's uniqueness error used to abort the whole tick; `PositionPlanManager.evaluate_once` now isolates each plan, so the error becomes a NEEDS_ATTENTION outcome plus a durable PLAN_EVALUATION_ERROR event for that plan and the remaining plans are still evaluated.
- **FIXED -- same-second Prepare (ACC-04, harness note).** Proposal ids now take the first free `-N` suffix and a lost same-id race becomes a clean 'click Prepare again' refusal (`tests/unit/test_p2_same_second_prepare.py`).
- **FIXED (wording) -- ACC-06/ACC-07.** The submission-boundary refusal for a working BUY now reads 'a position and/or working order(s) of N shares already exist in SYMBOL'.

## What is not end to end

- The broker and market-data WIRE is a scripted exchange (`tests/integration/_m100_fake_alpaca.py`): its fills, rejections, drops and quotes are what the tests tell it; it is not Alpaca and does not reproduce Alpaca's own rules. `SimulatedPaperBroker` (`simulation_paper.py`) is not driven by this matrix.
- Time is a virtual clock shared by host, wire and `now=` arguments; real market hours, exchange holidays and real latency are not exercised.
- The WSGI application is called in-process (no socket); `PlanManagerThread` is not started -- `PositionPlanManager.evaluate_once` is driven directly, exactly as the thread does.
- ACC-02's signal is the M090 Opportunity Engine on scripted bars; the matrix does not claim that signal has any edge, and the engine's candidate is not wired into Prepare (`prepare_v1_paper_candidate` evaluates the configured one-symbol watchlist itself).
