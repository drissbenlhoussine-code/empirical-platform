# M085 canonical authority contract closure — AUTH-2

Status: CORRECTED CANDIDATE. Local commit only at authorship time (pushed as part of the M088
mission's stack-propagation phase; not merged; not frozen). No Alpaca call, no Paper order, no
database mutation and no production-code change of any kind occurred as part of this closure.

Reviewed head: `77c2842ef75dcf17cb7002f240c10b65bee53444` (the real Alpaca Paper acceptance
evidence commit). Candidate: **`5c5dbb5700ac43981d4b87282488ae2d744b4a86`** (`5c5dbb5`).
Verification for the exact SHA: [verification.md](verification.md); logs in `runs-5c5dbb5/`.

## 1. The finding

`current-authority.json`'s `structural_limitations` still selected
`the_external_paper_submission_was_measured_blocked_by_quote_staleness`, whose sentence (in
`tools/render_m085_authority.py`) reads: *"The bounded external paper submission was MEASURED
BLOCKED, not completed..."* That became false at `77c2842`: the real Alpaca Paper acceptance run
on 2026-09-28 dispatched, was acknowledged (`pending_new`), had cancellation requested
immediately, and reconciled to a broker-confirmed terminal state of `CANCELED` with a filled
quantity of zero. The canonical "current authority" document — the one artifact this milestone
says is the single source of what M085 currently claims — was actively asserting a fact that was
no longer true. A governance defect, of the same shape as AUTH-1's, but narrower: no renderer
sentence was silently widened, and no code the contract describes changed at all. One documented
external-event fact went stale when the event it described was superseded by a later, real event.

## 2. What changed, precisely

One identifier, one-for-one, in `structural_limitations` only:

| Removed | Added |
|---|---|
| `the_external_paper_submission_was_measured_blocked_by_quote_staleness` | `the_external_paper_submission_completed_once_unfilled_and_canceled` |

New sentence: *"The bounded external paper submission was MEASURED COMPLETED, not blocked: the
order was dispatched, acknowledged by the broker (`pending_new`), cancellation was requested
immediately, and reconciliation observed a terminal broker state of CANCELED with a filled
quantity of zero. This is a single occurrence and is not a proof of fillability, repeatability, or
of any latency, queueing or execution-quality property; see `paper-acceptance-results.md` for the
measured numbers. The earlier 2026-09-10 MEASURED BLOCKED run remains recorded in git history and
is not restated here."*

Nothing else in any of the five tables changed. `proves`, `does_not_prove`, `database_enforcement`
and `intended_future_use` are byte-identical to the pre-closure contract. `structural_limitations`
holds the same 13 items it held before (a swap, not an addition or removal in count).

## 3. Why `authority_version` stays 2, and why this is not promoted to `proves`

AUTH-1 bumped the version because it added NEW structural guarantees — nine `proves` identifiers,
six `database_enforcement` identifiers, each pinned to code and SQL and proven by dedicated
mutation-test families — a material expansion of what the contract asserts is enforced. This
closure adds no guarantee of that kind. It corrects one factual claim about a single external
event. No `database_enforcement` value changed, no `proves` identifier was added or removed, and
no code path this milestone describes was touched. The existing test
`test_no_positive_claim_asserts_a_completed_external_submission` already forbade exactly the
tempting shortcut — recording the completed submission as something the contract "proves" — and
that test is unchanged and still passing: a single completed, unfilled, cancelled run is a
**limitation** (one occurrence, not a proof of fillability or repeatability), never a proof.

## 5. Tests fixed, and why each fix is honest rather than a weakening

- `TestTheBlockedSubmissionIsDeclaredNotHidden` → renamed
  `TestTheExternalSubmissionOutcomeIsDeclaredNotHidden`. Its two content tests now assert the
  identifier that is actually selected (`..._completed_once_unfilled_and_canceled`) and assert the
  evidence file states `RESULT: EXTERNAL PAPER SUBMISSION COMPLETED`, `**final state**:
  `CANCELED``, `**filled quantity**: `0E-8``, and contains neither `` `FILLED` `` nor `MEASURED
  BLOCKED`. Its third test (no positive "proves" claim) is unchanged.
- `TestAuthorityVersionTwoNamesTheRoundGuarantees.test_no_v1_identifier_was_dropped` — this test's
  job is to guarantee no *structural* v1 claim silently disappeared across a contract change. Of
  its three checked survivors, one
  (`the_external_paper_submission_was_measured_blocked_by_quote_staleness`) names no structural
  guarantee at all; it names the outcome of one external event, and that outcome changed. It was
  removed from the checked tuple with an inline rationale comment; the two genuinely structural
  survivors (`protection_against_a_database_owner_ddl_a_disabled_trigger_or_a_superuser`,
  `row_level_refusals_do_not_cover_truncate_drop_a_disabled_trigger_or_a_superuser`) are still
  checked, unchanged. The exact-count assertions in the same test (14/19/18/11 v1 items) are
  untouched and still pass, because the swap did not change any table's length.
