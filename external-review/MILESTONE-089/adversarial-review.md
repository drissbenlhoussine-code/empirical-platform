# MILESTONE-089 — adversarial review: 16 attack classes

Method: read the exact code each defense sits in (domain `__post_init__`s, CHECK constraints and
triggers, the composition roots' wiring, the architecture tests) rather than trusting a
docstring's claim. Classification per item: **PROVEN** (a test exercises the exact failure mode
and fails without the defense), **IMPLEMENTED** (the code path exists and was read, but no test
targets this exact scenario), **CLAIMED** (a defense exists but a residual gap remains and is
named), **BLOCKED** (not applicable / structurally impossible to reach).

| # | Attack | Verdict | Where the defense lives / residual risk |
|---|---|---|---|
| 1 | Short-position creation | **IMPLEMENTED**, residual risk named | `PositionExitRequest.side` is the literal `SELL_TO_CLOSE`; quantity is bounded to `attributable_quantity`, which CHECK constraints require to equal `broker_position_quantity` exactly, in both Store A and Store C. `SubmitAuthorizedPositionExitHandler` re-runs the FULL assessment (a fresh broker position read) immediately before dispatch and refuses if it no longer matches. **Residual**: between that re-verification and the broker's own order-matching, a true TOCTOU window exists at the broker (e.g. a corporate action or a concurrent manual sale reducing the held quantity between our re-check and Alpaca processing the SELL) that application code cannot close — Alpaca Paper accounts can be configured to permit shorting on a plain `sell`. This is the same residual class M085's own BUY path accepts for the analogous race, and is exactly why Phase 14's real acceptance run must observe an actual fill, not just the code path. |
| 2 | Over-closing quantity | **PROVEN** | `PositionExitPreview.__post_init__` refuses `request.quantity != position.attributable_quantity` and `!= position.broker_position_quantity`; `ck_position_exit_preview_full_close` / `ck_position_exit_preview_quantity_equals_broker_position` reproduce it as CHECK constraints in Store C (and Store A, unchanged); `ck_position_exit_attempt_filled_within_quantity` bounds the broker's OWN reported fill. Exercised by M087's existing domain/DB tests (environment-agnostic; reused). |
| 3 | Closing unrelated holdings | **BLOCKED** (no reachable route) | Every exit path (`AssessPositionExitHandler`, `PreviewPositionExitHandler`, the `/exit/review` route) is keyed by an `entry_intent_governance_id` the Owner is already looking at on the Active-trades page — there is no field, form or handler anywhere that accepts a free-form symbol or quantity. An unrelated manual Paper holding has no matching Store-B entry attempt, so `exit_eligibility` refuses at "no entry execution is on record for this position" before any broker call. A competing holding in the SAME symbol as a real entry is refused via `competing_entry_attempt_ids`. |
| 4 | Duplicate SELL (server-side retry) | **PROVEN** | `claim_dispatch`'s conditional `UPDATE ... WHERE consumed_at IS NULL` plus the partial unique index `uq_position_exit_attempt_one_active_per_entry` (Store C, mirrored from Store A) make a second claim for the same entry return the FIRST winner's attempt, never insert a second row. M087's concurrency tests cover this shape; reused unchanged. |
| 5 | Browser double-submit / two tabs | **PROVEN** | `PositionExitConsole.confirm` checks `active_for_entry` FIRST and returns "Already confirmed" for an existing attempt before ever calling authorize/submit again; the ticket is bound to one preview version and fingerprint. |
| 6 | Stale position/quote evidence | **CLAIMED**, finding | Position evidence: `AssessPositionExitHandler` always reads the broker position fresh (`fetch_position`), and `SubmitAuthorizedPositionExitHandler` re-runs it immediately before dispatch — proven fresh at send time. Quote evidence: `PreviewPositionExitHandler` requires a bid to exist and be positive, but — unlike M085's entry path — does **not** check the quote's `captured_at` against a maximum-age bound before pricing the exit's LIMIT order. This is lower-severity than a stale entry price (a stale, too-low limit on a SELL simply risks a slower fill, not an unsafe execution), but it is a genuine gap against the mission's "stale quote → REFUSE" requirement in the strict sense. **Finding, not blocking**: recommend adding an explicit quote-age bound to `PreviewPositionExitHandler` in a follow-up pass before real acceptance, or accepting the residual risk explicitly in the Owner's sign-off. |
| 7 | Order identity drift | **PROVEN** | `client_order_id` is derived, never generated (`derive_exit_client_order_id`, SHA-256 of entry+account+preview id); `ck_position_exit_*_client_order_id_prefix` CHECKs pin the `m087-` prefix in both stores; `exit_order_terms_mismatches` refuses to adopt a broker-echoed order whose symbol/side/quantity/type/price/TIF/extended-hours differ from the authorized request. |
| 8 | Broker/local disagreement | **PROVEN** | Same mechanism as #7, exercised on both the SUBMIT and RECONCILE paths (`_dispatch`, `ReconcilePositionExitHandler.handle`): a mismatch moves the attempt to `SUBMISSION_UNKNOWN`/leaves it unchanged and is never silently adopted. |
| 9 | Partial fill handling | **PROVEN** | `PartiallyFilled` is a real, non-terminal state; `_verify_closed` only acts on `attempt.fully_filled` (`state is FILLED and filled_quantity == quantity`); the console shows "Partially filled; the rest is still working. The position is reduced, not closed." |
| 10 | Position still > 0 after FILLED | **PROVEN** (the milestone's own mandatory rule) | `ReconcilePositionExitHandler._verify_closed` reads the broker position AFTER a full fill and only calls `mark_position_closed` when it reads exactly zero; otherwise it records `POSITION_NOT_ZERO_AFTER_FILL_EVENT_TYPE` and the attempt stays un-closed and flagged. `mark_position_closed`'s own DB constraint (`ck_position_exit_attempt_closed_requires_full_fill`) refuses to set `closed_position_verified_at` on anything but a FILLED, whole-quantity row. |
| 11 | Accidental Live endpoint | **PROVEN** | `ALLOWED_EXIT_ENVIRONMENTS` contains no `LIVE`; no `CapabilityStatus` anywhere in the repository carries `ExecutionCapability.LIVE` with `enabled=True`; `AlpacaPaperClient`'s endpoint is validated by `PaperEndpoint.from_url`, which refuses any URL but `https://paper-api.alpaca.markets`; architecture tests assert all of this from the live imported values, not source text. |
| 12 | Database cross-wiring (Store B/C confused) | **PROVEN** via the schema-head guards, residual named | Store C's own guard (`require_exact_m089_schema_head`) refuses any database not at exactly the M089 revision — including Store B, which sits at the M085 revision. `resolve_paper_exit_postgres_config` never reads `EMPIRICAL_PLATFORM_POSTGRES_DATABASE` (Store B's own variable); it reads a distinct `EMPIRICAL_PLATFORM_PAPER_EXIT_POSTGRES_DATABASE`. **Residual**: an operator who explicitly sets that override to Store B's actual database name defeats the naming separation — the schema-head guard is the backstop that still refuses in that case (Store B's `alembic_version` will never equal the M089 head), so the failure mode is a refusal, not silent corruption. |
| 13 | Schema migration of the M085 Paper DB | **PROVEN** structurally | No code in this milestone invokes `migrations/`'s chain (`alembic.ini`) against anything; Store C's own environment (`migrations_paper_exit/env.py`) resolves its target via `EMPIRICAL_PLATFORM_PAPER_EXIT_POSTGRES_DATABASE`, never `EMPIRICAL_PLATFORM_POSTGRES_DATABASE`. `tests/architecture/test_m089_paper_exit_boundaries.py` asserts the two `.ini` files name disjoint `script_location`s and the two `env.py` files do not import each other. |
| 14 | Credentials in logs | **PROVEN** (inherited) | `credentials_from_environment`'s redacted `repr`, request sanitization and `sanitized_body` handling are unchanged from M085/M087; `submit_close_order` reuses `submit_order`'s exact machinery rather than a new implementation, so the same coverage applies without a new gap to introduce. |
| 15 | False CLOSED / P&L shown in the UI | **PROVEN** | `PositionExitAttempt.position_closed` requires BOTH `fully_filled` AND `closed_position_verified_at is not None`; every UI surface (`ExitSummary.position_closed`, `realized_result()`) reads that property, never a looser condition; `realized_result` itself returns `None` unless `exit_attempt.position_closed` and both fill prices are proven positive Decimals. |
| 16 | Restart / recovery bugs | **PROVEN** (pending the fork's live-Postgres confirmation for Store C specifically) | `paper_operator_console_with_exit_runtime()` opens fresh `PostgresPersistenceService` instances for both stores on every process start; no in-memory cache survives a restart. M087's own integration suite already proves "a new process over the same database resumes correctly" for Store A's shape; `tests/integration/test_m089_paper_exit_postgres.py` (this milestone) extends the same proof to Store C. |

## Net assessment

15 of 16 attack classes are PROVEN or BLOCKED by an existing, machine-checked defense (mostly
inherited unchanged from M087, since the usecase/domain layer needed almost no changes to become
environment-agnostic). One (#6, quote staleness on the exit preview) is a genuine, low-severity
gap against the mission's strict "stale quote → REFUSE" requirement and is reported as a finding
rather than silently accepted or worked around. #1 and #12 carry named residual risk that
engineering can bound but not eliminate; both fail closed (a refusal or a flagged
`SUBMISSION_UNKNOWN`/`NEEDS_ATTENTION` state), never a silent bad outcome.
